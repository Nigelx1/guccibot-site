Engine

The Engine.

peony dropped the source and walked away. No announcement. No warning. Just excellence on the table. GucciBot picks it up, puts it in a gold frame, calls it home. No guesswork. No legacy baggage. Pure.

  • 5 midhooks surgically placed inside GD’s binary. physDt, physStepCount, restorePhysDt, earlyUpdate, frameUpdate. Exact 2.2081 offsets. Not guessed. Not estimated. Exact. The physics loop bends to our will because we asked it to, politely, with a hex editor.
  • Proper TPS bypass — the CCScheduler hook drives the physics loop at whatever TPS you set. 240 means 240 ticks per second. Not 60. Not 60 with interpolation. 240. Your inputs land where they land and they stay there.
  • SSB fix — the scroll speed bug that caused physics drift at certain speeds. Eliminated. Works in normal play, in recording, in playback, in layout mode. It does not come back. It is gone. Brrr.
  • Lock delta, two modes — Performance mode for playback speed, Accuracy mode for physics purity. Accuracy uses real-time scroll position delta to keep the timing tight. You pick based on what matters to you. Both are correct choices.
  • Full PracticeFix — the most complete SavedPlayerCheckpoint state capture of any public bot. Position, rotation, velocity, gravity, game mode, both players, full GJGameState. When you load a checkpoint it actually loads. Not approximately. Exactly.
  • Backwards stepping — step backwards through a level mid-attempt, one frame at a time. GucciBot saves a configurable number of frames as you play. You go back. The physics wind back. You try again from exactly there. Most bots cannot do this. Drip.
  • Intentional deaths — tell the bot that this death was planned. It records it in the replay as Death, RestartFull, or Restart. Playback recreates the reset at the right frame. The verifier sees a full attempt. Everything checks out. Hypothetically.
  • Macro diff viewer — load two replays and compare them frame by frame, up to 500 differences. See exactly where they diverge. Useful for debugging, for comparing attempts, for understanding why a run looks different. Drip and utility.
  • TPS mid-macro changes — change TPS during a recording and the new TPS is stored as an action in the replay. Playback reads it and switches TPS at that exact frame. The physics adjust. Nobody else stores TPS changes in the replay data itself.
  • Mirror inputs — flip which player is which during playback. Useful for two-player levels, for practice, for situations where controls are inverted.
  • Maintain gravity — gravity state is preserved on reset. Your player doesn’t randomly flip orientation when the level resets. It stays where it was.
  • Auto-flip on death — when the player dies, GucciBot automatically queues an input to flip gravity. Useful for specific skip setups. Sounds niche. Is extremely useful if you need it.
  • Prevent death — the bot intercepts the destroy call before the player actually dies and backsteps instead. Noclip without the visual pass-through. Physics stay intact. The level keeps running.
  • Noclip — full noclip with death flash, accuracy percentage display, and an auto-disable threshold. Set it to disable at 97% and it disengages automatically. Or leave it on and just vibe.
  • Noclip accuracy display — shows what percentage of the level you got through before dying. Optional. Visible in the HUD. Updates in real time. Pairs with the threshold.
  • Autoclicker — fully independent Hold Ticks, Release Ticks, and Clicks Per Hold per player, matching Silicate's own model, with a one-shot sync button between them. Stores as GBR6 Type C — 4 bytes no matter how long the level. The description of the pattern is stored, not the output. This is unique to GucciBot publicly.
  • Frame advance and frame stepping — pause the physics loop and step forward one frame at a time. Useful for precise input placement, for debugging, for watching a crash in slow motion with full composure.
  • Hotkeys for everything — every feature has a rebindable hotkey. Toggle noclip mid-run. Toggle recording. Frame advance. Backwards step. Intentional death. All keybindable. None of them conflict with GD unless you set them to.
  • Layout mode — strips the visual layer. Background becomes flat. Ground becomes flat. Decorative objects become invisible. The physics still run. You see the geometry, nothing else. Pure.
  • No mirror effect — suppress the visual flip when the level mirrors. Physics unaffected. Optional: recording-only mode so it only suppresses during record, not playback.
  • Bot settings presets — save your entire configuration as a named preset. TPS, speed, lock delta mode, SSB fix, backwards stepping, noclip threshold — all of it. Load it back with one click. Swap between setups instantly.
  • Metadata editor — rename any macro, change its author tag, edit the metadata without rerecording. It’s a file and the file has fields and you can change them. Organized.
  • Autosave at level end — when the level completes, the current macro saves automatically if a name is set. Optional. Defaults off. The kind of feature you forget about until you desperately need it.
  • Autosave on timer — saves the macro every N seconds during recording. Configurable interval. Runs in the background. Also the kind of feature you forget about until you desperately need it. Enable both.
  • Legacy format converter — loads old .brrr v1 macros and converts them to GBR6 in one click. Old files are not abandoned. They upgrade.
  • RNG lock — freezes the random seed so shake effects and randomized elements behave identically between attempts. Deterministic. Consistent. Locked.
  • Render tab — full video recording with codec dropdown (h264_nvenc, hevc_nvenc, libx264, av1 and more), audio codec dropdown (aac, libopus, libmp3lame), pixel format selector, separate video and audio args fields, resolution, FPS, bitrate, output path. Optional 4-track audio split too — combined mix, music, SFX, and frame-window cues, each on their own track instead of mixed into one. All configurable. All saved. All yours.
  • Click sounds — plays audio feedback on inputs during recording and optionally during playback. Configurable per player. P1 and P2 have separate packs. Background noise support.
  • Audio pitch with speedhack — when speedhack is active, the audio pitch scales with the speed. 2x speed, 2x pitch. Sounds natural. Doesn’t sound like a chipmunk. Actually sounds natural.
  • Frame extrapolation — visual position extrapolates between physics ticks. At 240 TPS the visuals update smoothly, not in discrete jumps. The game looks right. The physics are right. Everything is right.
  • HUD label system — customizable on-screen labels showing TPS, current frame, player position, velocity, rotation. Configurable scale, opacity, anchor position. Information where you want it.
  • 20 themes with 18 file extensions — GucciBot, ToosiiBot ×3, JaBot, GiddeyBot, BamBot, SexyyBot, JuiceBot, ButlerBot, SaweetieBot, MaybachBot, RomoBot, GrizzleyBot, Red Kingdom, LemonadeBot, BrrrBot, WakaBot, YoungstaBot, KnockerzBot. Each has its own color palette. Each saves macros with its own extension. The payload is always GBR6. The extension is the drip.

Pathfinder

No Recording.
No Macro.
It Finds One.

Open a level with nothing. Hit Pathfinder. It plays the level itself, dies, works out what had to be different, and tries again — thousands of times if that’s what it takes — until it has a run that reaches the end. Then it hands you the macro, named after the level, saved and ready. You recorded nothing.

☠
Death Is The Signal
It doesn’t read the level layout. It runs forward until GD’s own collision kills it, and treats that death as proof something earlier had to change. Then it looks back from there — past any stretch where no input could have changed anything, like the whole fall after walking off a ledge — for the input that gets further. No geometry parsing means nothing to get wrong about a 2.2 object nobody accounted for.
The game decides what kills you.
↶
Real Backtracking
Every input it tries at a decision point is crossed off there permanently. Run out of options and it restores a real checkpoint further back and takes the next branch instead. It never sits there retrying the same failed thing — the exact behaviour that makes other attempts at this useless.
Never tries the same thing twice.
✓
It Proves Its Own Answer
A solution stitched together from checkpoint restores isn’t the same as a macro that plays from frame zero. So before Pathfinder gives you anything, it replays the entire input list from a genuine cold start and requires it to reach the end again on its own. If it can’t, it isn’t a solution and it keeps looking.
Verified cold. Every time.
▤
Watch Or Don’t
Runs, depth, best frame, best percent — all live while it works. Leave the cover on and let it surprise you, or turn it off and watch it fail its way forward in real time, which is genuinely fun to sit through. Cancel whenever. It saves what it found.
Let it grind.
Straight Up: Where It’s At

Pathfinder is v1 and we’re not going to pretend otherwise. It is genuinely solid on cube — jumps, spikes, the stuff a level throws at you early. It is not there yet on ship, wave, robot, spider, or anything where surviving means a whole sequence of inputs instead of one well-placed press. That’s a limitation of how v1 searches, not a bug, and the next version is being designed around exactly that. Point it at a cube level and it’s real. Point it at a wave and it’ll grind. We’d rather tell you that than have you find out.

Why is it called GucciBot and not something else?
Because Nigelx1 is the creator and he has vision. The name was chosen before the bot was even built. The drip came first. The code followed. This is the correct order of operations.
What does “Brrr” mean?
It’s Gucci Mane’s signature ad-lib. It also describes the sound of a macro running perfectly. It also describes how you feel when a 2-byte compressed macro runs a 240 TPS playback without dropping a frame. It means many things. It means everything. Brrr.
How many build rounds did it take to make this?
Lost count somewhere past 40, across more internal versions than we're willing to number. MSVC compatibility issues, API mismatches, TTR/Silicate integration, slc shims, glaze removal, the whole journey, capped off with a full practice trainer nobody asked for and everybody needed. Claude.ai built basically the whole thing. A dawg fr.
Is .brrr the same as .toosii as the same as .ja?
Yes. The extension is the drip. The payload is always GBR6. Every single one. .brrr hits different than .sexyy but they decompress identical. Pick your theme like you pick your outfit. The physics don’t care. The fits do. Brrr.
Can I use GucciBot on a Mac?
No. Windows only. Geometry Dash is on Mac but GucciBot hooks into GD 2.2081 Win64 at specific binary offsets. You’d need different offsets for Mac. Also the renderer uses LoadLibraryW which is a Win32 API. Get Windows. Or ask Nigelx1 really nicely.
Why is the autoclicker delta compression unique?
Because instead of storing every single autoclicker press and release (which could be millions of inputs for a long level), GBR6 Type C stores the pattern description — hold ticks, release ticks, start frame. From that, the entire click sequence can be reconstructed at playback. 4 bytes for any autoclicker macro of any length. Nobody else has published this.
What is SLL and why is GucciBot top tier in it?
SLL stands for Silent Levels List — a GD community discipline focused on completing specific levels with extreme precision. GucciBot uses the Silicate engine which has the most accurate TPS bypass and delta locking of any public bot. With kepe’s Astral additions, the physics accuracy is competitive at the top of that scene. We updated the rating from “Competitive” to “Top Tier” partway through building this website. Why are there two Trainer tabs?
The Jupiter tab is the original — built around one level, permanently, on purpose. The new Trainer tab is the same toolset generalized to work with whatever macro you actually have loaded. One is a dedication. The other is a utility. Both are real. Use whichever one your grind actually needs.

Whatever's next will probably be for new features, not for fixing things that were already broken -- probably. That is growth. That is the drip mentality. Brrr.
